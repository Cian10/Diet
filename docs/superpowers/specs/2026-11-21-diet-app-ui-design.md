# 健身饮食 macOS App UI 设计方案

日期：2026-11-21  
状态：用户已整体通过视觉方向，待审阅本文后进入实施计划

## 1. 目标与边界

本方案只负责现有 macOS App 的视觉、布局、组件与状态表达，不改变饮食记录、营养计算、目标确认、LLM 请求、趋势规则或本地优先的隐私边界。

### 目标是

- 让用户打开 App 后先看到“今天最需要做什么”，再看到支撑判断的关键数据。
- 保持 macOS 原生使用习惯，同时建立清楚、克制、可记忆的产品气质。
- 让“已确认”“模型估算”“部分未知”“分析失败”在视觉和文案上都可区分。
- 用同一套语义色、排版、间距和组件覆盖今天、日记、趋势、我的、首次设置、记录与确认流程。
- 同时支持系统浅色、深色、窗口缩放、键盘操作和 VoiceOver。

### 不在本次范围

- 不新增账号、云同步、社交、导出、HealthKit 或餐食计划功能。
- 不重写业务模型、ViewModel、仓库、LLM 客户端或营养算法。
- 不改变现有导航的四项一级结构：今天、日记、趋势、我的。
- 不引入自定义字体、复杂插画系统、持续动画或全屏仪表盘。
- 不要求重新设计 iOS 条件编译页面；本次交付目标是 macOS 14+。

## 2. 已确认视觉方向

| 决策 | 结果 |
| --- | --- |
| 视觉气质 | A · 轻盈健康仪表盘 |
| 首页信息组织 | 单一重点卡片，其次是三个关键读数与最近记录 |
| 色彩 | P1 · 苔绿 + 暖象牙白 |
| 外壳 | S2 · 品牌化原生分栏 |
| 字号体系 | 系统 SF 字体，中文与日文均随系统本地化 |
| 深色模式 | 自动跟随 macOS 系统外观 |

一句话概括：**轻量专注（Quiet Focus）——把每天最重要的一步放到最前面，让数据作为下一步行动的依据，而不是压力来源。**

视觉参考板保存在 `.superpowers/brainstorm/98747-1795195062/content/design-board.html`，仅作为过程记录，不属于源码交付。

## 3. 设计原则

### 3.1 先行动，后总览

“今天”页首先回答“下一餐怎么吃”；热量、蛋白质、完成天数只作为支持信息。不得把首页做成等权重卡片墙。

### 3.2 绿色是操作与完成，不是背景墙

主绿色只用于主按钮、当前导航、完成状态和关键进度。大面积使用暖象牙白、浅苔绿和中性描边，避免“整页健康绿”。

### 3.3 橙色必须说明不确定性

橙色只用于模型估算、部分营养未知、目标待确认和需要注意的偏差。任何橙色状态必须同时有文字或图标说明，不能仅靠颜色传达。

### 3.4 原生外壳，品牌内容

保留 `NavigationSplitView` 的 macOS 分栏、键盘导航、窗口缩放和系统材质。品牌化集中在侧栏顶部、选中胶囊和内容区层级，不替换窗口交通灯或系统菜单。

### 3.5 安静但有层次

静态卡片以描边和细阴影区分，不使用厚重投影或玻璃拟态。只在单一重点卡、Sheet 与浮层上加强层次。

## 5. 字体与排版

### 5.1 字体

- 中文、英文和数字统一使用系统字体 SF Pro，不内嵌第三方字体。
- 页面标题使用系统语义字号，视觉目标为 26–28 pt、semibold、字距约 -0.02 em。
- 卡片标题 17 pt semibold；正文 13 pt regular；辅助信息 11 pt regular。
- 关键热量和克数使用 `.monospacedDigit()`，但不使用等宽字体整体替换系统字体。
- 所有正文使用动态字号语义值，支持 macOS 辅助功能字号放大。

### 5.2 层级

| 层级 | 字号/字重 | 用途 |
| --- | --- | --- |
| 页面标题 | 28 pt / semibold | 今天、饮食日记、趋势、我的 |
| 区块标题 | 17 pt / semibold | 今日重点、周四概况、记录流程 |
| 正文 | 13 pt / regular | 说明、建议、表单辅助文字 |
| 数据主值 | 20–28 pt / semibold，等宽数字 | 热量、重量、完成率 |
| 辅助信息 | 11 pt / regular | 时间、状态、单位、来源 |
| 微型标签 | 10 pt / medium，全大写仅用于英文 | `TODAY`、`LOCAL`，不可用于关键中文信息 |

正文一行建议不超过 42 个中文字符；长段落优先拆分为短段或列表。数值与单位之间留一个半角空格。

## 6. 间距、圆角与层级

- 基础间距为 4 / 8 / 12 / 16 / 24 / 32 pt。
- 页面外边距：28 pt；窗口宽度小于 960 pt 时降为 20 pt。
- 区块间距：24 pt；同一区块内元素间距：8–12 pt。
- 卡片内边距：16–20 pt；重点卡 18–22 pt。
- 控件圆角：9 pt；普通卡片：14 pt；重点卡：16 pt；Sheet：18 pt。
- 侧栏宽度 200–224 pt，最小内容宽度约 720 pt；默认窗口约 1100 × 760。
- 静态卡片：1 pt 描边 + 极轻阴影；重点卡可使用轻微绿色渐变与装饰圆弧。
- 不使用模糊玻璃作为默认卡片背景；系统材质只用于侧栏、Sheet 和弹出层。

## 7. 组件规范

### 7.1 一级侧栏

- 使用 `NavigationSplitView` + `List`，保留原生窗口控制、键盘导航与系统侧栏行为。
- 顶部品牌区包含 32 pt 圆角方形图标、产品名和当前日期/模式缩写。
- 导航项使用 16 pt 图标 + 11 pt 标签，当前项为浅绿底、`primaryText` 文字和 700 字重。
- 侧栏底部固定个人入口，展示头像、个人空间和设置图标；不增加第二套设置导航。
- 侧栏背景始终使用语义令牌 `sidebar`；浅色与深色值由主题自动切换，不使用深色品牌侧栏。

### 7.2 页面标题区

- 左侧为标题与一行副标题；右侧为日期胶囊和主操作。
- 主操作固定为“＋ 记一餐”，点击进入现有记录流程。
- 页面标题使用真实页面语义，不使用营销口号。
- 在窄窗口下允许按钮落到下一行，但不得截断标题或压缩到不可点击。

### 7.3 单一重点卡

- 标题为“今日重点”，内容回答一个具体动作，如“记录晚餐”“确认目标”或“补充蛋白质”。
- 右侧显示完成率或当天关键进度，右上角提供直接动作按钮。
- 正文只保留一个动作与最多两个数值；不得堆叠三个以上建议。
- 完成率 0–100%，不使用红色表示“不足”；缺口使用中性语言。
- 待确认目标时，卡片优先显示目标确认，不显示普通餐食建议。

### 7.4 指标卡

- 首页只保留三个指标：已摄入热量、蛋白质、本周达标天数。
- 数值 20 pt semibold，单位 10 pt regular；标签 11 pt secondary。
- 指标卡不承担跳转，除非该卡片有明确的下一级内容；本次不需要新增跳转行为。

### 7.5 餐食行

- 结构为：32 pt 餐别图标、食物名称、时间/状态/热量、状态标记。
- 标题最多两行；超出使用 `.lineLimit(2)` 并以省略号结束。
- 状态至少有“已确认”“待确认”“分析失败”三种，分别使用绿色、橙色、红色语义色。
- 删除与编辑放在记录详情或明确上下文菜单，不在首页常驻显示破坏性按钮。

### 7.6 按钮

- 主按钮：`primary` 实心、`onPrimary` 文字，圆角 9 pt，高度 32–36 pt。
- 次按钮：白色/表面色底，1 pt 描边，深色文字。
- 文本按钮：用于“返回修改”“手动记录”“查看建议”，颜色为 `primary` 或 `inkSecondary`。
- 危险按钮仅在确认对话框中显示，使用 `danger`，不得和主按钮并排造成误触。
- 不允许只用图标表示“保存”“删除”“重试”；图标旁必须有文字或可访问标签。

### 7.7 状态提示

- 空态：一句说明 + 一个明确主操作，不使用大面积插画占位。
- 加载态：按钮文字变为“正在分析…”，禁用重复提交，并保留取消路径。
- 估算态：橙色“估算”标签 + 说明“确认前请核对”；不能自动取估算范围中点。
- 部分未知：橙色提示并复述未知项目名称，不把未知值当作 0。
- 错误态：保留所有用户输入与原图，提供“重试”和“手动补全”。
- 成功态：绿色文字/图标，不使用长时间 Toast 作为唯一反馈；保存后回到对应页面并刷新汇总。

## 8. 页面设计

### 8.1 今天

结构：

1. 页面标题“今天”与副标题。
2. 日期胶囊与“＋ 记一餐”。
3. 单一重点卡。
4. 三个关键指标。
5. “今天吃过”的最近记录，最多显示 8 条。

规则：

- 首个重点卡根据状态优先级决定内容：
  1. 目标待确认：显示“确认今日目标”。
  2. 存在分析失败/待确认草稿：显示“完成这一餐的确认”。
  3. 当前有目标且未记录晚餐：显示“记录晚餐”。
  4. 已完成目标或缺口较小：显示“今天已完成，查看日记”或“保持当前节奏”。
- 完成率仅代表进度的视觉表达，不把超出目标自动标红。
- 仍需保留当前营养不完整提示；用橙色提示说明“当前为部分合计”。
- 最近记录点击后仍进入现有确认/详情页，不新增行为。

### 8.2 日记

结构：

1. 标题“饮食日记”、一句副标题、主记录按钮。
2. 日期导航：前一天、当前日期、后一天、日历选择；日期范围沿用现有规则，不新增限制。
3. 当日能量与蛋白质摘要卡。
4. 按早餐、午餐、晚餐、加餐分组的记录行；空组显示虚线卡与添加入口，入口复用现有记录流程。
5. 若现有记录带有 `note`，在对应记录行下方只读展示；本次不新增备注编辑能力。

规则：

- 可选择日期范围沿用现有 `DatePicker` 规则，不新增未来日期限制；任何日期都必须显示真实数据，不允许把非今天样式化成“今天”。
- 记录按 `consumedAt` 排序；跨日期行为沿用现有业务规则。
- 删除入口在记录详情或上下文菜单；确认对话框使用中性文案“删除这条饮食记录？”
- 同日汇总、目标差额和未知项提示必须与 ViewModel 输出来源一致。

### 8.3 趋势

结构：

1. 标题“趋势”、七日周期说明和日期范围。
2. 每日摄入图：柱形 + 目标虚线 + 当前日强调；必须有文本摘要。
3. 右侧概况卡：记录天数、平均热量、目标完成率、体重变化；仅显示现有 ViewModel 提供的字段。
4. 洞察卡：最多 2–3 条解释性洞察，不生成确定因果结论。
5. 周期复盘与待确认建议：显示待确认数量和查看入口。

规则：

- 记录不足 3 天时不生成趋势性结论，只展示原始数据与“数据不足”说明。
- 图表颜色不能作为唯一区分；目标线使用虚线，当前日使用图形/标签说明。
- 支持 Swift Charts 的轴标签与 VoiceOver 摘要；不得只通过 hover tooltip 读取。
- 本次不新增 30 天或阶段切换数据功能；若未来扩展周期，必须由独立需求与业务规则驱动。
- 阶段切换、目标变更等实际业务标记按现有数据保留。

### 8.4 我的

结构：

1. 标题“我的”、隐私副标题、“编辑档案”次按钮。
2. 个人档案摘要卡：头像、基础身体摘要、当前阶段胶囊。
3. 目标、阶段、身体数据、饮食偏好、LLM API、隐私与数据的六项摘要卡；目标/阶段/身体数据/偏好入口复用现有 `ProfileRootView` 与编辑 Sheet，LLM 入口复用 `LLMSettingsView`。
4. 底部数据说明：本地优先、仅主动分析时上传。

规则：

- `SettingsHubView` 仍作为个人入口；导航到 `ProfileRootView`、`LLMSettingsView` 等现有页面。
- API Key 保存后不显示明文；保留 Keychain 边界。
- “编辑档案”保持 Sheet 形式；视觉上使用页面级次要按钮，不抢主记录入口。
- 删除、导出、清空数据等破坏性能力若未实现，不在 UI 中伪造。

### 8.5 首次设置

- 页面使用居中表单卡，宽度 560–620 pt，背景为 `canvas`。
- 顶部显示产品名与隐私说明，不新增多步骤进度或营销插画；现有表单字段顺序保持不变。
- 身体信息、活动水平、饮食偏好、忌口与过敏按现有表单顺序分组。
- 未填身体数据时明确标注“将不会自动生成目标”，不得暗示会有虚假默认值。
- 底部固定主按钮“开始使用”；错误信息显示在对应字段或表单顶部。
- 遵循现有 `OnboardingView` 的校验与保存逻辑，不新增注册、账号或云端步骤。

### 8.6 文本记录

- macOS 上使用桌面 Sheet；窄窗口沿用同一 Sheet 的可滚动布局。内容宽度约 620 pt。
- 顶部为“记一餐”、餐别、时间，下方为输入类型分段控件“文字描述 / 图片识别”。
- 文本域至少 100 pt 高，辅助文字说明估算不确定性。
- 主操作“分析这一餐”；次操作“不调用模型，手动记录”。
- 分析中锁定重复提交，输入不丢失；错误态保留原文。

### 8.7 图片记录

- 先显示得到图片后的预览区域，再显示“上传并识别”主操作。
- 支持从文件和剪贴板粘贴的现有入口；没有图片时显示可点击的空态，不创建假记录。
- 图片预览、删除/替换、分析状态与错误提示占据稳定布局，避免分析时页面跳动。
- 原图与压缩副本的实际保存边界沿用 `ImageService` 与 `PhotoLoggingService`。

### 8.8 确认页

- 桌面宽度下使用左右分栏：左侧原图/原文上下文，右侧识别项、份量与估算标记。
- 窄窗口下改为上下堆叠，确认按钮始终可见。
- 每项显示名称、份量、估算状态和营养来源；未知项必须有明确提示。
- 底部固定“返回修改”与“确认并保存”，避免用户在长列表中找不到动作。
- 确认后写入已有记录仓库并刷新来源页；不绕过重复保存保护。

## 9. 深色模式

- 跟随系统外观，不提供 App 内手动主题切换。
- 侧栏、卡片、图表、状态色和 Sheet 使用语义令牌，不依赖 `Color.black` / `Color.white` 硬编码。
- 深色下绿色主按钮为 `#64AD83` 深底文字，保证对比度，不使用高饱和荧光绿。
- 阴影在深色下弱化，层级主要由描边和表面色差表达。
- 所有页面至少在浅色、深色各完成一次视觉检查。

## 10. 动效与交互

- 标准过渡 150–220 ms，缓动使用系统 `.easeOut` / `.easeInOut`。
- 按钮按下缩放不超过 2%，不使用持续呼吸、循环漂浮或自动轮播。
- 针对 Reduce Motion 关闭非必要位移，只保留透明度或不再动效。
- Sheet 从窗口底部出现，键盘焦点落在第一个可编辑字段；关闭时恢复原页面焦点。
- 焦点环、Tab 顺序和 Return/Escape 行为遵循 macOS 原生控件；不能因为自定义背景而移除焦点状态。
- 颜色与图形状态不可成为唯一反馈，需配合文字。

## 12. 验收标准

### 视觉与交互

- 1100 × 760、960 × 640、1280 × 800 三种尺寸下无横向溢出、文字截断或不可点击的主操作。
- 浅色和深色模式均通过视觉检查；语义色与正文对比度符合 Accessibility。
- 侧栏四项可用键盘切换；Tab、Return、Escape 行为不被自定义样式破坏。
- 文本、图片、手动记录三条路径均可完成确认并返回对应页面刷新汇总。
- 估算、待确认、部分未知、分析失败、空记录均有可见文案和下一步操作。
- 不显示伪造的默认身体数据、零值营养结果或未经确认的保存状态。

- 现有依赖、SwiftData schema、Keychain 边界和 LLM 网络行为不变。
