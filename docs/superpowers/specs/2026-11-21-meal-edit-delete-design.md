# 饮食记录编辑与删除修复设计

日期：2026-11-21

## 目标与数据安全

让“今天”和“日记”中的已有饮食记录都能通过明确的详情页按钮编辑或删除。保留现有 `MealEntry`、SwiftData schema、数据库位置和原始输入，不迁移、清空或重建数据库。实施前备份当前数据库。

编辑只更新用户选中的记录；校验失败时不保存更改。删除只删除用户明确确认的记录，本机图片是否一并删除仍由用户选择。持久化失败时不关闭详情页，并显示错误。

## 最小改动方案

- “今天”的记录点击进入与“日记”相同的 `MealDetailView`，不再直接进入确认编辑器。
- `MealDetailView` 提供清晰的“编辑并重新确认”和“删除记录”按钮。
- 删除确认由详情页统一展示，沿用“保留本机图片／删除本机图片”选择。
- 删除回调返回是否成功；成功后刷新汇总并退出详情，失败后留在详情页。
- 日记 ViewModel 的删除方法返回成功状态；今天 ViewModel 使用同一 meal store 与 image store 实现相同删除规则。
- 保留现有编辑确认页和营养计算逻辑，不增加撤销、云端同步或存储重构。

## 验证

- 内存仓库测试：日期过滤、删除和图片保留／删除规则不回归。
- SwiftData 测试：已确认记录修改后内容更新且原记录 ID 不变，删除后只移除目标记录，其他记录保留。
- 运行默认与 SwiftData 全部测试，并完整构建 macOS App。
- 构建和自动化测试只使用内存或测试数据，不对真实数据库执行修改或删除。
