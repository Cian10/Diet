# 07：文本饮食记录

## 核心流程

1. 用户输入自然语言，例如“中午吃了一个麦当劳汉堡、一份中薯条和一杯无糖可乐”。
2. 调用 LLM 拆分食物、品牌、数量、餐别和时间。
3. 如果关键信息不足，优先提出一个最影响结果的问题。
4. 获取或估算每项食物的营养数据并标明来源。
5. 展示可编辑确认页。
6. 用户确认后保存 `MealEntry` 和 `EntryComponent`。
7. 使用本地引擎重新计算每餐和每日汇总。

## 确认页必须支持

- 修改食物名称、数量和份量。
- 修改餐别和用餐时间。
- 删除错误项目、添加遗漏项目。
- 查看估算假设、营养来源和可信等级。
- 对手动输入的营养成分进行编辑。
- 将结果保存为常用食物或套餐（第二阶段）。

## 快捷与回退能力

- 手动记录复用同一食物确认页和保存流程，但不调用 LLM；营养数据可由用户按标签录入。
- 无网络或模型失败时转为手动记录。
- 支持重新分析原始文本，但不能覆盖已确认记录。
- 后续支持“与昨天相同”“份量减半”等引用历史记录的操作；仍需确认后保存。
- 语音转文字只作为后续输入扩展，不改变后续处理流程。

## 模块验收

- 麦当劳示例能拆成独立项目，必要时追问汉堡具体名称。
- 用户把一份改为半份后，营养结果由本地引擎正确重算。
- 未确认草稿不进入今日摄入。
- 重复点击保存不会产生重复餐食。
- 请求失败后原文仍保留，可重试或手动完成记录。
