# 14：macOS 桌面版迁移设计

日期：2026-11-19
状态：已获用户批准，按本文实施迁移

## 目标与兼容策略

将现有个人健身饮食 App 的交付目标从 iPhone 调整为仅供用户本人在自己的 Mac 上运行的原生 macOS 应用。现有产品闭环、数据模型、营养规则、LLM 配置和确认流程保持不变。

- 用户当前系统已确认为 macOS 27.2.1。
- 应用最低部署目标保持 macOS 14；高于部署目标的 macOS 27 可以运行该应用，无需使用 macOS 27 专属 API。
- 技术栈保持 SwiftUI、SwiftData、Swift Charts、UserNotifications、Keychain 和本地文件存储。
- 默认不开发账号、云同步、公共后台或 Windows 版本。
- 本次不新增 HealthKit、数据导出或其他独立功能。

## 代码复用边界

### 直接保留

- `DietCore` 中的领域模型、SwiftData schema 和仓库协议。
- 营养计算、目标引擎、档案与阶段、文本记录、推荐、趋势和复盘服务。
- OpenAI 兼容文本／图片请求、结构化结果校验和错误处理。
- `ImageProcessor`、`LocalImageStore` 和 `PhotoLoggingService`：继续负责图片解码、JPEG 上传副本、本地原图及失败重试。
- API Key 的 Keychain 存储和 LLM 设置仓库。
- 现有单元测试及本地 stub，不为了迁移调用真实付费 API。

### 桌面适配

- `project.yml` 的应用和框架目标改为 macOS 14，移除 iPhone 设备族和 iOS 权限配置。
- 保留 SwiftUI 页面、表单、ViewModel 和识别确认页；macOS 主外壳使用 `NavigationSplitView` 侧栏，仍包含“今天、日记、趋势、我的”。
- 图片记录页在 macOS 上使用“从文件选择”和“粘贴剪贴板图片”，不使用相机或相册权限。
- iOS 专属实现可以留在条件编译中作为历史兼容代码，但不属于当前生成、测试和交付目标。

## 桌面导航与窗口

```text
NavigationSplitView
├── 今天
├── 日记
├── 趋势
└── 我的
    ├── 个人档案与健身阶段
    └── LLM API 设置
```

- 侧栏只负责切换现有页面，不复制业务逻辑。
- 默认窗口约 1100 × 760，允许调整大小；内容最小区域约 960 × 640。
- 首次设置、档案编辑、文本记录、图片记录和确认页沿用现有导航及表单。
- 不增加菜单栏常驻、全局快捷键、多窗口或多实例数据同步。

## 图片输入与识别流程

```text
粘贴剪贴板图片 ─┐
                ├→ DesktopImageImporter → 图片 Data
从文件选择图片 ─┘                              ↓
                                  PhotoLoggingViewModel
                                             ↓
                                   PhotoLoggingService
                                  ├── 本地保存原始图片
                                  ├── 生成压缩 JPEG
                                  ├── 调用多模态 LLM
                                  └── 使用本地原图重试
                                             ↓
                                  现有确认页与营养计算
```

### 文件选择

- 使用 SwiftUI `fileImporter`，内容类型限制为 `UTType.image`，一次选择一张图片。
- 对安全作用域文件只在读取期间调用 `startAccessingSecurityScopedResource`，结束后立即释放。
- 将文件读为 `Data` 并验证 ImageIO 可以生成图片缩略图；验证通过后才更新预览。
- 原文件随后可以移动或删除，记录重试只依赖 App 已保存的本地原图。
- 用户取消选择不报错、不创建记录；无法读取或不是有效图片时显示错误并保留当前草稿。

### 剪贴板粘贴

- 图片记录页提供“粘贴剪贴板图片”按钮，并提供 Command–V 快捷键。
- 仅在用户主动粘贴时读取 `NSPasteboard.general`，不监听剪贴板变化，也不注册全局快捷键。
- 支持剪贴板中的 PNG、TIFF、JPEG 以及其他可由 ImageIO 解码的图片类型。
- 支持从 Finder 复制图片文件后粘贴；多个文件中取第一张有效图片。
- 无图片、图片损坏或文件无法读取时显示可理解错误，不覆盖当前已选择的有效图片。

### 识别行为不变

- 新输入只替换图片获取方式，识别仍通过现有 `PhotoLoggingService`。
- 原图只保存在本机；只有用户点击“上传并识别”后才发送压缩副本给所配置的模型供应商。
- 分析期间禁用重复导入和提交；失败可重试或改用手动记录。
- 识别结果必须由用户确认，未确认记录不计入每日摄入。

## 错误与隐私

- 区分“剪贴板没有图片”“图片无效”和“文件无法读取”。
- 导入失败不触发 LLM 请求，不删除已有原图，不清空文本或食物草稿。
- API Key 不进入日志、源码、SwiftData 普通字段或剪贴板。
- 通知仍使用 macOS 本地通知，通知文案遵循最小暴露原则。

## 验收

### 自动测试

- 现有 SwiftPM 测试继续在 macOS 14 部署目标下通过。
- 文件导入能读取有效 PNG/JPEG，拒绝文本或损坏图片。
- 剪贴板图片数据和 Finder 文件 URL 的解析使用纯数据测试，不实例化或读写用户真实剪贴板；`NSPasteboard` 适配器在应用中单独验收。
- 无图片和非法图片返回明确错误，不覆盖已有输入。
- 导入后仍复用同一图片服务、确认流程和营养计算。

### 完整 Xcode 中的应用验收

- 生成 macOS 工程并编译、启动，完成首次设置和重启后的 SwiftData 持久化检查。
- 验证文件选择、截图粘贴、Finder 复制粘贴、大图、非图片和取消操作。
- 验证 Keychain 保存、真实供应商文本／图片请求、失败重试和离线手动记录。
- 验证窗口缩放、深色模式、通知权限和通知中心展示。

仅运行 SwiftPM 测试时，不宣称上述应用内项目已经通过。
