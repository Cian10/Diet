# 10：营养空缺与食物推荐

## 职责边界

推荐功能消费本地计算后的目标差额、当天已吃食物、当前阶段和用户偏好。规则引擎先产生可执行候选方案，LLM 只负责可选的语言解释和多样化表达。

## 输入

- 当天目标、当前摄入和剩余量。
- 当前时间、餐别及是否有后续训练。
- 当前健身阶段。
- 偏好、忌口和过敏食物。
- 常用食物及可用营养数据。

## 规则示例

- 蛋白质不足且热量仍有余量：推荐高蛋白食物和明确份量。
- 热量接近目标但蛋白质不足：优先选择相对低脂、高蛋白方案。
- 后续有训练且碳水不足：在符合目标的情况下提供训练前后选择。
- 已超出目标：中性总结，不推荐禁食、极端运动或第二天惩罚性补偿。

## 推荐输出

每项建议必须包含：

- 当前缺口或问题。
- 推荐食物和建议份量。
- 推荐后的预计营养变化，由本地引擎计算。
- 所采用的营养来源和估算性质。
- 可替换选项及忽略建议的方式。

## 安全与质量

- 过敏和明确忌口是硬过滤条件。
- 不生成疾病治疗建议。
- 数据不足时优先建议补充信息，而不是编造精确推荐。
- 用户拒绝某类食物后应更新偏好或减少同类推荐。

## 模块验收

- 所有推荐前后的数值均可由本地计算复现。
- 过敏和忌口食物不会出现在候选列表。
- 无网络时仍能提供基础规则推荐。
- LLM 润色失败不会改变或阻塞已经生成的候选方案。
