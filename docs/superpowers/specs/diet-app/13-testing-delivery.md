# 13：测试、验收与交付顺序

## 测试层次

### 单元测试

- 食物份量换算、营养汇总和显示舍入。
- 目标计算、目标差额和实际热量缺口。
- 阶段版本、单日覆盖和历史目标。
- 推荐过滤、调整规则和通知调度。
- LLM JSON 解析、缺字段、错误类型和异常值。

### 集成测试

- 文本输入到确认、保存、汇总和日记展示。
- 图片输入到识别、修改份量、确认和汇总。
- 模型失败后的草稿恢复、重试与手动回退。
- 切换阶段后未来目标更新而历史不变。
- 调整建议确认、拒绝和通知跳转。

### 真实设备验证

- 相机和相册权限、不同图片方向及大图上传。
- 通知权限、锁屏显示和免打扰。
- 离线、弱网、API 超时和密钥错误。
- 动态字体、深色模式、跨零点和时区变化。
- 个人开发者签名安装后的 Keychain 与本地数据表现。

## 固定测试样例

逐步建立一组人工核对的数据集：

- 有包装标签的单一食品。
- 麦当劳汉堡、薯条和无糖饮料组合。
- 一份中式混合餐和多种烹饪方式。
- 份量减半、增加一项和删除一项。
- 多食物图片、模糊图片和非食物图片。
- 数据不足、营养字段未知和模型返回非法 JSON。

模型输出测试使用保存的样例响应，避免每次测试都依赖实时 API；少量真实 API 测试单独执行。

## MVP 总体验收

- 可以独立完成档案、阶段和每日目标设置。
- 文本描述经过确认后能形成正确、可编辑的饮食明细。
- 首页与日记营养汇总一致，修改份量后立即重算。
- 无网络不影响手动记录、历史查看和计算。
- 所有估算均有来源或假设，未知不被当作零。
- 单日偏差不会自动修改长期目标。
- API 失败不丢失原始输入，密钥不出现在日志中。

## 推荐交付顺序

1. 建立工程、领域模型和本地持久化。
2. 完成用户档案、阶段方案及纯本地计算测试。
3. 完成手动记录、今日首页和日记，先形成离线可用版本。
4. 接入统一 LLM 服务和文本记录。
5. 增加拍照记录并复用确认及计算流程。
6. 增加趋势、推荐、每周复盘和提醒。
7. 最后评估 HealthKit、数据导出或其他扩展。

## 每个模块的完成定义

- 功能符合对应模块文档及总索引约束。
- 相关单元测试和关键集成测试通过。
- 真实设备上完成必要人工验证。
- 错误、空状态和离线行为已处理。
- 文档中的接口或规则若发生变化，已同步更新。
- 不以后续模块尚未实现为理由留下静默失败或不可解释的占位数值。
