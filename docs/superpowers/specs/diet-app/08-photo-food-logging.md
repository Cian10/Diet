# 08：图片饮食记录

## 核心流程

1. 用户在 macOS 上从文件选择一张食物图片，或主动粘贴剪贴板中的图片／Finder 图片文件。
2. 图片输入适配器读取并验证图片数据，失败时保留当前输入和草稿。
3. 本地保存原始记录，为 API 创建适当压缩的上传副本。
4. 用户点击“上传并识别”后，才调用统一视觉模型接口。
5. 返回多个候选食物、份量范围和识别假设。
6. 用户补充品牌、重量、烹饪方式等关键信息。
7. 复用文本模块的确认页和本地营养计算。
8. 用户确认后才计入每日摄入。

## 图片输入要求

- 文件选择使用 `UTType.image` 过滤，一次选择一张；读取安全作用域文件后立即释放权限。
- 剪贴板只在用户点击粘贴或使用页面内 Command–V 时读取，不后台监听。
- 支持常见 ImageIO 图片格式、截图数据以及 Finder 复制的图片文件 URL。
- 无图片、文件无法读取或图片损坏时给出明确错误，不覆盖当前有效图片。
- 不请求相机或相册权限，不提供桌面相机流程。

## 识别要求

- 一张图中的多个食物应分别列出，允许用户拆分和合并。
- 无法判断重量时显示估算范围，不显示虚假的精确克数。
- 区分“能识别食物种类”和“能可靠估计份量”两种能力。
- 看不清、非食物图片或模型失败时，可切换为文本描述或手动记录。
- 图片上传前明确告知用户将发送给所配置的模型供应商。

## 图片与数据

- 原图默认只保存在本机，并与餐食记录关联；识别重试不依赖原始外部文件路径。
- 删除记录时按用户选择处理关联图片。
- 图片加载失败不能删除已经确认的营养明细。
- 导入失败、取消选择或权限失败时提供文本和手动记录回退。

## 模块验收

- PNG/JPEG 文件、截图剪贴板和 Finder 文件 URL 均能进入同一预览及识别流程。
- 空剪贴板、非图片和损坏图片不会发起模型请求或覆盖有效输入。
- 多食物图片进入可编辑确认页，而不是自动生成不可修改的总热量。
- 用户可修改估算份量并立即看到重算结果。
- 未确认图片记录不影响每日汇总。
- 上传失败和无效图片均有可恢复路径。
- 文本和图片最终使用同一领域模型、确认逻辑和计算引擎。
