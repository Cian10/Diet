# 08：拍照饮食记录

## 核心流程

1. 用户拍照或从相册选择图片。
2. 本地保存原始记录，为 API 创建适当压缩的上传副本。
3. 调用统一视觉模型接口。
4. 返回多个候选食物、份量范围和识别假设。
5. 用户补充品牌、重量、烹饪方式等关键信息。
6. 复用文本模块的确认页和本地营养计算。
7. 用户确认后才计入每日摄入。

## 识别要求

- 一张图中的多个食物应分别列出，允许用户拆分和合并。
- 无法判断重量时显示估算范围，不显示虚假的精确克数。
- 区分“能识别食物种类”和“能可靠估计份量”两种能力。
- 看不清、非食物图片或模型失败时，可切换为文本描述或手动记录。
- 图片上传前明确告知用户将发送给所配置的模型供应商。

## 图片与数据

- 原图默认只保存在本机，并与餐食记录关联。
- 删除记录时按用户选择处理关联图片。
- 图片加载失败不能删除已经确认的营养明细。
- 拍照权限和相册权限被拒绝时提供系统设置指引及文本回退。

## 模块验收

- 多食物图片进入可编辑确认页，而不是自动生成不可修改的总热量。
- 用户可修改估算份量并立即看到重算结果。
- 未确认图片记录不影响每日汇总。
- 权限拒绝、上传失败和无效图片均有可恢复路径。
- 文本和拍照最终使用同一领域模型、确认逻辑和计算引擎。
