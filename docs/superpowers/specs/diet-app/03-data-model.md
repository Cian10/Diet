# 03：数据模型与持久化

## 建模原则

- 内部统一使用标准单位，保留用户原始描述和原始份量单位。
- 保存营养来源及记录时的营养快照，避免食物库更新后历史记录悄悄变化。
- 模型结果和用户修改分开保存，便于追踪估算与纠正。
- 目标、阶段和调整建议均保留日期与版本。

## 核心实体

| 实体 | 关键内容 |
|---|---|
| `UserProfile` | 年龄、身高、当前体重、可选性别和体脂率、活动水平、偏好、忌口、过敏信息 |
| `PhasePlan` | 阶段类型、开始/结束日期、目标规则、训练日规则、版本、状态 |
| `DailyTarget` | 日期、热量和宏量营养素目标、来源方案版本、是否单日覆盖 |
| `FoodItem` | 名称、品牌、份量基准、营养数据、来源、地区、外部标识 |
| `NutritionSnapshot` | 每份或每 100g 的热量及营养素、来源类型、估算说明 |
| `MealEntry` | 用餐时间、餐别、原始文本、可选图片、确认状态、备注 |
| `EntryComponent` | 食物、数量、原始单位、换算克数、营养快照、估算范围 |
| `EstimationRecord` | 输入类型、模型原始结构化结果、可信等级、缺失信息、用户修正 |
| `WeightRecord` | 日期、体重、可选来源 |
| `DailySummary` | 日期、摄入汇总；必须可由当天已确认明细重建 |
| `AdjustmentProposal` | 触发依据、旧目标、新目标、解释、状态、用户确认日期 |
| `NotificationSettings` | 开关、用餐时间、提醒规则、每周复盘时间 |

## 来源类型

至少区分：

- 用户按包装标签录入。
- 可核验的食物营养数据。
- 模型根据品牌或常见配方估算。
- 用户手动修正。

未知营养字段使用“未知”，不得自动当作零。

## 状态与时间规则

- 未确认的记录是草稿，不计入每日汇总。
- 已确认记录再次编辑时，保留原始输入并重新计算。
- 用餐记录按用户本地时区归属日期；跨零点时以实际用餐时间为准。
- 阶段变化不删除旧 `DailyTarget`。
- 删除用餐记录采用明确确认，并同步重建汇总。

## 模块验收

- 同一食物库项目被修改后，既有历史餐食仍保持当时的营养快照。
- 草稿、已确认和识别失败记录可以明确区分。
- 任意一天的汇总能从餐食明细重建。
- 目标历史、模型估算和用户修正均可追溯。
