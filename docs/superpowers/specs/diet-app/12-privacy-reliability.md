# 12：隐私、安全与可靠性

## 隐私

- 身体数据、饮食记录、目标和图片默认仅存本机。
- 只有用户主动发起分析时，相关文本或图片才发送给其配置的模型供应商。
- 设置页说明所用供应商、发送内容和本地存储方式。
- 不接入广告、第三方行为统计或默认数据上报。
- API Key 使用 Keychain，不写入源码、普通偏好字段、日志或剪贴板。
- 只有用户主动粘贴时才读取剪贴板，不监听剪贴板变化；文件选择只在读取期间使用安全作用域权限。
- 通知内容遵循最小暴露原则。

个人本机运行不等于密钥绝对安全；不得把该配置方式直接当作未来公开分发的安全方案。

## 数据可靠性

- 用户确认前保留草稿，应用退出或请求失败不能丢失原始输入。
- 保存操作避免重复提交，编辑和汇总更新保持一致。
- 所有外部响应都视为不可信输入，执行结构、类型、单位和范围校验。
- 网络失败、限流、无效密钥、服务超时和内容无法识别使用不同错误状态。
- 离线时可使用手动记录、历史查看、营养计算和基础规则推荐。

## 估算透明性

- 区分标签数据、可核验数据、模型估算和用户修正。
- 份量不确定时展示范围、假设和需要补充的信息。
- 不把缺失营养数据当成零。
- 不用“AI 精确识别”等宣传性表述误导用户。

## 后续数据管理

后续可增加本地 JSON/CSV 导出和备份恢复。导出必须包含记录日期、食物明细、营养来源及目标版本；恢复时避免重复导入。

## 模块验收

- 静态检查和实际日志中均找不到明文 API Key。
- 取消图片分析不会产生网络请求。
- 终止应用或断网后，已保存记录和未提交原文可恢复。
- 恶意或异常模型响应不会创建非法营养数值或导致崩溃。
