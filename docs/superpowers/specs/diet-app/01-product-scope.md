# 01：产品范围与 MVP

## 目标

明确首版要解决的问题，防止在基础记录和计算尚未可靠前扩展过多功能。

## 用户与核心场景

唯一用户正在进行健身，希望根据增肌、减脂、维持和休息／恢复阶段管理饮食。典型场景包括：

- 用一句中文描述一餐，而不是逐项搜索食物。
- 粘贴食物截图或选择本地食物照片，确认识别出的食物和份量。
- 查看当天还剩多少热量和蛋白质可摄入。
- 在目标不足或超量时获得可执行的建议。
- 根据连续趋势而非单日波动调整后续目标。

## 功能分期

### 第一阶段：可用 MVP

- 用户档案、健身阶段和目标方案。
- 手动记录及文本饮食记录。
- 识别结果确认、份量修改和营养重算。
- 热量、蛋白质、碳水和脂肪的每日汇总。
- 今日首页、饮食日记和基础目标提醒。
- 本地持久化、API 设置和失败重试。

### 第二阶段：视觉与推荐

- 文件或剪贴板图片识别。
- 多食物拆分、估算范围和文本回退。
- 常用食物、常用套餐和收藏。
- 营养空缺分析及个性化食物推荐。

### 第三阶段：趋势与适应

- 七日趋势、每周复盘和目标调整建议。
- 训练日／休息日的单日目标。
- 体重趋势和阶段复盘；健康平台接入不纳入当前 macOS 版本。

## 非目标

首版不追求医学级准确性，不承诺仅凭文字或照片得到真实摄入量。产品价值是减少记录成本、让估算依据透明，并帮助用户持续执行合理目标。

## 模块验收

- 所有后续功能都能归入上述阶段。
- 新增需求不会绕过“用户确认”和“本地计算”两个核心约束。
- MVP 不依赖图片识别、健康平台、云同步或复杂推荐即可独立使用。
