# 05：营养计算与目标引擎

## 营养计算

所有数值计算在本地执行，输入为已确认的食物明细和营养快照。

### 计算顺序

1. 将份、个、毫升等单位换算为可计算的基准份量；无法可靠换算时要求用户确认。
2. 根据数量和营养快照计算每个食物项目。
3. 汇总每餐和每日摄入。
4. 与当天 `DailyTarget` 比较，得到剩余量或超出量。
5. 仅在显示层四舍五入，内部保留足够精度。

初版宏量营养素能量换算采用可配置系数，默认蛋白质和碳水 4 kcal/g、脂肪 9 kcal/g。包装标签中的标示能量应保留来源，不应因小幅换算差异被静默覆盖。

## 目标计算

目标引擎按以下顺序工作：

1. 在身体数据足够时估算基础代谢；默认采用 Mifflin–St Jeor 公式。
2. 结合日常活动和训练估算总消耗，避免把同一活动重复计算。
3. 根据阶段规则形成目标热量建议。
4. 根据可配置的体重比例或用户设定确定蛋白质和脂肪目标。
5. 将剩余热量分配给碳水，或允许用户完全手动设置。
6. 展示计算依据和关键假设，由用户确认。

数据不足时允许直接输入热量与营养目标，不为了调用公式而猜测身体信息。

## 两个不同指标

- `estimatedExpenditure - actualIntake`：实际热量缺口。
- `targetIntake - actualIntake`：目标差额。

界面不得把两者都简称为“剩余热量”。运动消耗若数据不可靠，应显示估算性质，不自动建议把全部运动热量吃回。

## 微量营养素

初版不作为核心目标。后续添加时，如果食物数据不完整，应显示“数据不足”或覆盖比例，不能把未知累计成零。

## 模块验收

- 同一组输入重复计算得到一致结果。
- 修改份量、删除食物或切换日期后，汇总正确更新。
- 目标差额和实际热量缺口分别计算、分别展示。
- 缺少数据、除零、负数、异常单位和极端值均有明确处理。
- 计算引擎在无网络、无 LLM 的情况下可完成全部单元测试。
